# Fish Shell Config — This Machine

Knowledge skill: the verified layout of THIS Mac's fish setup and the rules that keep it working.
Every fact below was verified on this machine (2026-08). Do not generalize from bash habits —
fish differs, and this machine differs from stock fish.

## Machine truth

- Shell: `/opt/homebrew/bin/fish`, **fish 4.3**, on macOS (Darwin, Apple Silicon, Homebrew at `/opt/homebrew`).
- `~/.config/fish/config.fish` is a **symlink into the Nix store** (`...-home-manager-files`), regenerated by
  home-manager. **NEVER edit it or its target.** It defines managed aliases, sources `hm-session-vars.fish`,
  prepends `~/.nix-profile/bin` to PATH, and runs `starship init fish | source`.
- Editable surfaces (real directories, safe to write):
  - `~/.config/fish/functions/*.fish` — autoloaded on demand (lazy; loaded only when first called).
  - `~/.config/fish/conf.d/*.fish` — sourced at startup, **lexical order, before config.fish** (verified).
    No numbering convention is in use; if ordering matters, encode it in the filename.
  - `~/.config/fish/completions/` — mostly fisher-generated; leave alone unless authoring completions.
  - `~/.config/fish/fish_variables` — universal variables store (managed by fish itself; edit via `set -U`, not by hand).
- Plugin manager: **fisher** with plugins `jorgebucaran/fisher` and `jorgebucaran/nvm.fish`.
- Prompt: **starship** (binary from the Nix home-manager profile). Theme: catppuccin via `conf.d/plugin-catppuccin.fish`.
  `conf.d/fish_frozen_theme.fish` and `fish_frozen_key_bindings.fish` are fish-4.3 auto-generated — **do not edit**.

## Load order and the shadowing rule (verified empirically)

Startup order: `/etc/...` → `hm-session-vars.fish` → `conf.d/*.fish` (lexical) → `config.fish` (home-manager).

Consequence — the shadowing rule: **anything config.fish defines always wins over conf.d**, because config.fish
runs last. Managed aliases (`cc`→claude, `o`→oil, `of`→oil-float, `oo`, `oz`→oil-zed, `opencode-config`,
`claude-config`) therefore cannot be overridden by a conf.d file or by an autoload function file: by the time
the user types the name, the alias-function already exists, so the autoload never fires. To change a managed
alias, edit the home-manager source (locate the active generation with `home-manager generations`, then find
the flake/module defining `programs.fish`) — or simply pick a new local command name.

## Decision table — where a change goes

| Need | Put it in | Notes |
|---|---|---|
| New command (any logic) | `functions/<name>.fish` | Autoloaded; the default choice. Read `references/authoring-and-testing.md` first. |
| Env var, tool hook, secret export | `conf.d/<name>.fish` | Runs at startup; guard with `type -q` and `test (uname) = Darwin` where relevant. |
| Change a managed alias | home-manager source | See shadowing rule above. Never edit the symlink. |
| Persistent PATH entry | `set -U fish_user_paths ...` or home-manager | `fish_user_paths` already carries `~/bin`, fnm, `~/.npm-global/bin`. |
| New secret from Keychain | `conf.d/<tool>-keychain.fish` | Follow the pattern in `references/environment-and-secrets.md`. |
| Prompt / theme change | home-manager / starship config | Do not create `fish_prompt.fish`; starship owns the prompt. |
| One-shot script | anywhere, validate + stub-test | Same gates as functions; see `references/authoring-and-testing.md`. |

Abbreviations (`abbr`) are interactive-only expansions; aliases in fish are just functions. Prefer a function
file — it is autoloaded, discoverable, and testable. Register abbrs in a conf.d file only if expansion-in-place
is genuinely wanted.

## Authoring rules (non-negotiable gates)

1. Read `references/authoring-and-testing.md` **before writing any function file** — it carries the template,
   guards, and the full test pattern.
2. **Format gate:** `fish_indent -w <file> && fish_indent --check <file>` must pass. pi-lens blocks unformatted
   fish files (verified: a mis-formatted `--description` line fails the gate).
3. **Syntax gate:** `fish -n <file>` must pass.
4. **Behavior gate:** stub-test the logic with a scenario harness (`fish /tmp/test.fish <scenario>`) before
   declaring done. The harness pattern and its scoping gotcha live in the reference.

## Machine gotchas (verified)

- **Scope:** a `set -l` at the top level of a script is INVISIBLE inside functions it calls. In test harnesses
  pass context with `set -g` or env vars, never top-level `set -l`.
- **No word splitting:** `$var` and `"$var"` are identical lists; quoting is never needed to prevent splitting.
  Command substitution splits on newlines only.
- **`pi update --extensions`** (plural) updates all packages; `pi update --extension <source>` updates one.
  `piup` (in `functions/`) depends on this distinction.
- **Two Node version managers coexist:** nvm.fish plugin (fisher) and fnm (in `fish_user_paths`). PATH order
  decides which wins; check `command -v node; node -v` before debugging Node issues.
- Lists are 1-indexed; `$argv` replaces `$@`/`$1`; `$status` replaces `$?`.

  `agent-enhance`, `prompt`, plus fisher/nvm internals.

  plugins (`plugin-fisher`, `plugin-catppuccin`), frozen theme/keybindings (never edit).

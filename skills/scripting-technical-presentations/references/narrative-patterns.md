# Patrones narrativos para presentaciones técnicas

Leer este archivo solo cuando sea necesario elegir o combinar una arquitectura de guion.

## 1. Cambio conceptual

Usar para docencia, capacitación, adopción de prácticas o temas con errores intuitivos frecuentes.

1. Solicitar una predicción concreta.
2. Mostrar la respuesta intuitiva o concepción previa sin ridiculizarla.
3. Introducir un dato, demostración o caso que produzca conflicto útil.
4. Reconstruir el modelo correcto paso a paso.
5. Aplicarlo a una segunda situación para verificar transferencia.
6. Delimitar cuándo el nuevo modelo deja de ser suficiente.

No fingir una controversia inexistente. No usar confusión sin resolución.

## 2. Investigación en forma de reloj de arena

Usar para congresos, seminarios, defensas y actualizaciones científicas.

1. Abrir con el problema amplio que importa a la audiencia.
2. Reducir hasta la brecha exacta de conocimiento.
3. Formular pregunta, hipótesis o objetivo.
4. Presentar solo el método necesario para juzgar la evidencia.
5. Ordenar resultados por fuerza inferencial, no por orden de análisis.
6. Interpretar qué cambia y qué permanece incierto.
7. Volver al panorama amplio con implicaciones y próximos pasos.

Evitar una introducción bibliográfica exhaustiva y una sección de métodos desproporcionada.

## 3. Decisión técnica

Usar para comités, arquitectura, gobernanza, compras, implementación y liderazgo.

1. Declarar la decisión requerida.
2. Resumir el estado actual y el costo de no decidir.
3. Definir criterios de evaluación antes de mostrar opciones.
4. Comparar alternativas con la misma evidencia y supuestos.
5. Exponer trade-offs, riesgos y reversibilidad.
6. Recomendar una opción y explicar por qué domina bajo esos criterios.
7. Cerrar con decisión, responsable, próximo hito y condición de revisión.

Entregar la recomendación temprano. No convertir una reunión de decisión en una charla de descubrimiento.

## 4. Incidente, seguridad o calidad

Usar para análisis clínico, operativo, de ciberseguridad o confiabilidad.

1. Definir el estado esperado.
2. Describir la desviación observable sin culpabilizar.
3. Reconstruir detección, respuesta y consecuencias.
4. Separar causa próxima, factores contribuyentes y condiciones latentes.
5. Mostrar barreras que funcionaron, fallaron o no existían.
6. Proponer controles jerarquizados y verificables.
7. Declarar riesgo residual, responsables y seguimiento.

Evitar detalles identificatorios, morbo y narrativas de “error humano” que oculten el sistema.

## 5. Demostración técnica

Usar para software, dispositivos, procesos y prototipos.

1. Mostrar el problema real y la restricción relevante.
2. Establecer una línea base observable.
3. Explicar el principio de la solución antes de la interfaz.
4. Ejecutar un caso representativo.
5. Mostrar una prueba verificable del resultado.
6. Ejecutar o describir un caso límite o fallo conocido.
7. Cerrar con requisitos, límites y siguiente decisión.

Preparar una ruta alternativa cuando la demo en vivo pueda fallar. No usar una demo feliz como prueba universal.

## 6. Híbrido para audiencia mixta

Usar cuando conviven especialistas, líderes y disciplinas adyacentes.

- Mantener un hilo principal de problema → evidencia → implicación.
- Insertar inmersiones técnicas breves y señalizadas.
- Resumir cada inmersión en una conclusión comprensible para todos.
- Reservar derivaciones, validaciones extensas y tablas completas para el anexo.
- Preparar preguntas por perfil: método, operación, seguridad, costo e impacto.

## Aperturas funcionales

Elegir una apertura que ya haga trabajo argumental:

- predicción que revele un modelo mental;
- anomalía o dato que obligue a explicar;
- caso concreto que represente el problema sin sustituir la evidencia;
- conclusión directa cuando se necesita decidir;
- contraste entre práctica actual y resultado posible;
- demostración breve que establezca la pregunta.

Rechazar citas ornamentales, historias desconectadas, estadísticas gigantes sin contexto y preguntas retóricas cuya respuesta no importa.

## Cierres funcionales

El cierre debe:

1. responder la pregunta o tensión de apertura;
2. repetir la tesis con palabras más precisas, no idénticas;
3. declarar qué cambia en comprensión, práctica o decisión;
4. mantener visibles las condiciones y límites;
5. terminar en una frase completa, no en una diapositiva de “gracias”.
